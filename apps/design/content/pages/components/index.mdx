## Where components live

NoteKit follows hexagonal architecture — the UI is a driving adapter. The specimens here
document the visual language; each product surface owns its own implementation and converges
by consuming the same tokens, never by sharing component code.

| Surface | Package / path | Basis |
| --- | --- | --- |
| Product (web, desktop, mobile) | `@notekit/core` → `adapters/driving/components` | Bespoke React, monochrome `.nk` theme, Inter |
| Backoffice (admin) | `apps/backoffice/.../components/ui` | shadcn/ui (Radix primitives) + Tailwind v4 |
| Marketing | `apps/landing/components` | Bespoke, animation-heavy, DM Sans |

## Registry roadmap

The [theme is installable today](/installation) via the shadcn registry. Per-component
installables (`npx shadcn add …/button.json`) follow once these primitives are extracted into
publishable, dependency-light source. This section grows one real component at a time — it
never lists a component that isn't rendered here.
