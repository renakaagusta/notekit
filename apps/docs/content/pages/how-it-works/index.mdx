This section explains **how NoteKit is designed and why**. If you just want to use it, start with the
[quickstart](/get-started/quickstart); come back here when you want to understand what's happening
underneath.

Everything rests on three ideas that reinforce each other.

<SystemArchitectureDiagram />

## 1. Your vault is a Git repository

Notes, tasks, and secrets are files in a Git repo. History, attribution, and audit come from Git
itself — no proprietary database, no lock-in. One vault can hold many projects.
→ [The vault](/how-it-works/the-vault)

## 2. Content is end-to-end encrypted

Everything private is encrypted **on your device** before it is stored, so the files in that Git repo
are ciphertext. The server holds encrypted blobs and a little structural metadata — never your titles,
bodies, or secrets, and never your keys.

The keys that decrypt your data are **derived or generated on your device and never leave it**. That
single fact is what makes the server unable to read anything — the [zero-knowledge](/how-it-works/zero-knowledge)
guarantee.
→ [Encryption](/how-it-works/encryption) · [Devices & trust](/how-it-works/devices-and-trust)

## 3. One core, many surfaces

The web, desktop, mobile, CLI, and MCP server are thin front-ends over one shared core — including the
encryption. They don't reimplement anything; they call the same logic. That's why an agent can do
anything you can, and why every surface encrypts the same way.
→ [Architecture](/how-it-works/architecture)
