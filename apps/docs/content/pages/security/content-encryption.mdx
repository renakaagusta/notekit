Every note, task, link, and secret is encrypted with **[age](https://age-encryption.org)**, a small,
audited, IETF-track encryption format. NoteKit uses the `age-encryption` library (a JS implementation).

## The cipher

age is an **AEAD** (authenticated encryption with associated data) scheme:

- A random **file key** encrypts the payload with **ChaCha20-Poly1305** — ChaCha20 for confidentiality,
  Poly1305 for a tamper-proof authentication tag.
- The file key is then **wrapped to each recipient** using **X25519** (Elliptic-Curve Diffie-Hellman).
  One ciphertext can carry many recipients; each gets their own wrapped copy of the file key in the
  header.
- The result is **armored** — a text-safe `-----BEGIN AGE ENCRYPTED FILE-----` block — so it stores
  and diffs cleanly in Git.

Because it is AEAD, any bit-flip in a stored file is detected on decrypt; the server cannot silently
alter your notes.

## Encrypting and decrypting

```ts
// encrypt
const enc = new Encrypter();
for (const recipient of recipients) enc.addRecipient(recipient);
const armored = armor.encode(await enc.encrypt(plaintext));

// decrypt
const dec = new Decrypter();
dec.addIdentity(myIdentity);
const plaintext = await dec.decrypt(armor.decode(armored), 'text');
```

## Who the recipients are

In the current **envelope** model, content is encrypted to a **single vault key**, and that vault key
is separately wrapped to all your devices (see [Envelope encryption](/security/envelope-encryption)).
When you share an item with another person, their verified device keys are added as extra recipients
for that one item (see [Sharing](/security/sharing-and-revocation)).

## What is encrypted vs. what is cleartext

Each item is stored as a `.md.age` file: **cleartext YAML frontmatter** followed by the **armored
ciphertext** of the private fields. Some structural metadata is deliberately left in cleartext so the
app can render a sidebar, a board, and a sync tree without decrypting everything first.

```text
---
v: 1
encrypted: true
kind: note
id: 8f3c…
createdAt: 2026-08-29T…
updatedAt: 2026-08-29T…
folder: work            # cleartext, so the sidebar tree resolves
---
-----BEGIN AGE ENCRYPTED FILE-----
…armored ciphertext of { title, body, tags, … }…
-----END AGE ENCRYPTED FILE-----
```

| Item | Encrypted (private) | Cleartext (metadata) |
| --- | --- | --- |
| Note | title, body, tags, linked notes | id, timestamps, folder path |
| Task | title, body, assignee, labels | id, timestamps, status, priority, due date |
| Link | URL, title, annotations | id, timestamps, folder path |
| Secret | the secret value | id, timestamps |

Leaving ticket **status/priority/due-date** and note **folders** in cleartext is a conscious trade-off
so the board and sidebar work offline without decrypting the whole vault. The [threat model](/security/threat-model)
spells out the full list of what this exposes.

<Callout>
Filenames are opaque: items are stored under their UUID (`notes/&lt;id&gt;.md.age`), not their title — so
the filename itself never leaks the subject of a note.
</Callout>
