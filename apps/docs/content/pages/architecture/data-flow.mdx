Here is what actually happens when you save a note — on any surface. The path runs **inward** (adapter
→ use case → domain) and then **outward** (outbound port → transport → backend → Git). The encryption
happens on your device, before anything is sent.

## Step by step

1. **Driving adapter.** The web editor, `notekit note new`, or the `notes_create` MCP tool receives
   your input. This layer carries no business logic — it just gathers the command.
2. **Use case (application).** A single, pure function merges your command with any existing note,
   fills defaults, preserves `createdAt`, advances `updatedAt`, and computes the file path. It's
   testable with in-memory ports — no network, no clock, no disk.
3. **Encryption (domain).** If the vault is encrypted, the private fields (title, body, tags) are
   sealed with `age` to the vault key's recipient. Structural metadata (folder, timestamps) stays in
   cleartext frontmatter so the app can render without decrypting. See
   [content encryption](/security/content-encryption).
4. **Outbound port.** The use case calls `VaultPort.writeFile(path, content, sha)` — an interface, not
   an HTTP detail. The `sha` enables safe create-vs-update (optimistic concurrency).
5. **Driven adapter → transport.** The port's implementation calls the `@notekit/api-client` HTTP
   client, which every surface shares.
6. **Backend relay.** `apps/api` (Hono) authenticates the request, checks vault access, and relays the
   **already-encrypted** bytes to the Git provider. It never decrypts.
7. **Git commit.** The provider (Forgejo/GitHub/GitLab) writes the blob and commits it, authored by the
   device or agent that made the change — so history and attribution are plain Git.

## Why the same trace works on every surface

Because steps 2–7 live in the shared core, the web app, CLI, and MCP server all run the *identical*
path — they differ only in step 1 (how the command is gathered) and in which key store and auth mode
the composition root wired up. This is what "[agent parity](/mcp#agent-parity)" means concretely: the
same use case, reached from three different driving adapters.

<Callout>
Reads are the mirror image: the transport fetches ciphertext (delta-pulled by Git blob sha and cached
locally), then the device decrypts it with its own key. The server is never in possession of a key that
could read it.
</Callout>
